# Semantic correctness and regression coverage audit

This audit evaluates the six areas in the Rosetta review's differential matrix against Forge at `0f4908fc50f2794a59624815e412408fdc0c7a83` plus the regression tests described below. T1 calls for independent observations of defined guest behavior, separate checks for rejected operations, and retention of existing coverage across Debug and Release PEs with baseline and `default<O2>` native IR. Five gaps gained regression tests, including independent observation of service calls after a terminal guard. ## Regression cases and independent expectations

| Baseline gap | Added evidence |
| --- | --- |
| Full-width ADC/SBB | Each of the four `checkWideCarry` vectors starts with only CF available and set to one, and uses a zero right operand. Each instruction must supply all six result flags. In architectural flag positions (mask `0x8d5`), incrementing signed maximum gives signed minimum and `0x894`. Decrementing signed minimum gives signed maximum and `0x814`. Adding to unsigned maximum gives zero and `0x55`. Subtracting from zero gives unsigned maximum and `0x95`. PF uses the low byte even for a 64-bit result. Unicorn independently executed `48 83 d0 00` (ADC) and `48 83 d8 00` (SBB) with initial RFLAGS = 3. [Integer unit](../../tests/unit/integer.cpp) |
| Masked dword SHR | Twelve operand pairs cover CL counts 0, 1, 31, 32, 33, 63 and 64. The effective count is `CL & 31`. At zero the previous CMP flags survive. Otherwise CF is the last bit shifted out, PF is even low-byte parity, and ZF/SF come from the dword result. The fixture packs the result into the low dword and CF/PF/ZF/SF at bits 32/40/48/56. Shifting 6 right by one gives 3, CF=0 and PF=1, for a packed value of `1099511627779`. Other pairs exercise a nonzero upper dword and distinguish preserved CMP flags from flags recomputed after a masked-zero shift. The fixture consumes only defined flags. [Assembly](../../tests/differential/fixtures/arithmetic/integer_cases.S) · [Manifest](../../tests/differential/manifests/arithmetic_shift_dword.json) |
| Different flag availability at one callee | Five additional pairs reach the same helper from two distinct callers. The helper preserves flags when SF is set and otherwise compares DL with itself. The CMP caller supplies DL values 0, 255 and 16. After subtracting one, the first two preserve LAHF bytes `0x97` and `0x82`. The third starts with AF set and the helper replaces it, yielding `0x46`. The TEST caller reads ZF after both returns, getting zero for 128 and one for 1. Two independent mutations insert LAHF into private copies of the PE, one at the helper's entry and one at the TEST path's SETZ continuation. Both require a lifting-stage `LIFT_UNDEFINED_FLAG` for AF at that exact instruction and no published IR. | Adjacent backing intervals | `test_scalar_access_across_adjacent_sections` extends a zero-filled PE section to the start of the next writable section, with identical permissions. The architectural expectations follow the Intel instruction entries for ADC, SBB, SHR, CMP, TEST and LAHF. An instruction can define a flag value on a particular execution while a shared body lacks proof that every caller supplies that flag. Forge intersects available definitions at a callee entry and applies the callee's return effect separately at each call site. The shared context carries physical bits through flag-preserving code. Guest consumers must also pass the availability proof. ## Supported boundaries

- The compiler models 16 x64 GPRs with four legacy high-byte aliases. Variable-count shifts conservatively reject consumers of OF when a count greater than one is possible. Narrow logical shifts also restrict CF when the count can reach the operand width. Undefined AF after TEST makes LAHF unavailable. [Register views](../../compiler/src/lift/operands.cpp) · [Instruction contracts](../../README.md#lift-and-run-a-native-function)
- Recovered register calls require a statically proven target. Jump tables require a recovered bound and stable entries. General indirect dispatch and x86-32 execution are outside the supported set. [Recovery contracts](../program-architecture.md)
- Generated scalar loads and stores require the entire access in one permitted interval. Stack access additionally enforces byte validity and active return-slot protection. The checked runtime bridge can copy across adjacent permitted rows after validating the entire request, and each registered row borrows its owner's backing. [Generated stack](../../compiler/src/lift/memory.cpp) · [Image resolver](../../compiler/src/lift/image_memory.cpp) · [Runtime transfer](../../runtime/src/guest_memory.cpp) · [Registration](../../runtime/src/registration.cpp)
- The typed lifted entry takes two guest integers. `functions/recursive` exercises a six-argument guest-to-guest call. Marshalling a fifth argument at callee-entry RSP + 40 into a native service and supporting guest callbacks both await a corresponding service or re-entry contract. [Guest call fixture](../../tests/differential/fixtures/functions/calls.c) · [Runtime ABI](../runtime-architecture.md#guest-addresses-and-calls)
- Function-level guards trap the native host. The process-artifact entry returns a structured fault and retires the guest invocation. Recoverable Windows SEH, floating-point and divide faults would require defined guest state and cleanup at the fault site. Host callers must also synchronize conflicting generated and bridge accesses to shared bytes. The bridge's registration and copy locks do not serialize guest instructions. [Runtime lifecycle](../runtime-architecture.md#12f--process-lifecycle-integration) · [Fault model](rosetta-lessons.md#6-exceptions-and-faults) · [Guest memory ordering](rosetta-lessons.md#7-atomics-and-ordering)

### Terminal guard before GetLastError

The original fault probes could observe the expected signal even if a misplaced service call ran first. The checked-memory PE now exports `guard_then_service`. It allocates a 40-byte frame, stores eight bytes at `RSP + 32 + RCX`, calls the imported `GetLastError`, and returns. Each child starts the same executable with a fresh instance, live thread and last-error value of 1234. Only the store offset changes. [Assembly fixture](../../tests/fixtures/checked-memory.s) · [Fixture exports](../../tests/fixtures/generate.py)

At entry to the getter, the linked shim writes one `G` byte directly to the child's stdout pipe with `write(2)`, then calls the real runtime getter. The harness checks the returned value on normal completion. Python drains the pipe, captures stderr separately, and checks the complete marker bytes and child status with a ten-second timeout. A failed marker write aborts the harness. [Native shim](../../tests/support/checked_memory.cpp) · [Parent assertions](../../tests/integration/test_checked_memory.py)

| Store offset and destination | Baseline IR | `default<O2>` IR |
| --- | --- | --- |
| 0, eight-byte local above shadow space | Exit 0, one `G` | Exit 0, one `G` |
| 8, protected entry return slot | SIGTRAP, zero bytes | SIGTRAP, zero bytes |

`make test PRESET=dev BUILD_TESTING=ON CTEST_ARGS='-R guest_checked_memory'` passed fixture setup and the linked integration. `make test PRESET=release BUILD_TESTING=ON CTEST_ARGS='-R "guest_checked_memory|guest_imports"'` also passed all three selected CTests.

In a disposable copy of the canonical IR, the failing edge of the store's stack bounds and return-slot check called the instrumented getter and then branched to the original trap. In both variants the valid case still passed. The invalid child still received SIGTRAP, emitted one `G`, and failed the integration assertion. This identifies the guard reached by the invalid input.

The native stage ran `make format-check`, `make lint`, and all 34 CTests in both Debug and ASan/UBSan. The reference stage rebuilt 71 PEs per configuration twice, verified byte reproducibility, passed 142 fresh Wine captures and all five Wine runner tests. Both native variants passed for every enabled function in both PE configurations, totaling 244 comparisons. All 22 differential integration tests passed. Coverage run `54850ac1-ec30-40d5-a807-5e1fc548a45e` recorded 61 passing functions per configuration, zero mismatches and zero errors, and satisfied the reviewed baseline. [Coverage baseline](../../tests/differential/coverage-baseline.json) · [Gate protocol](../../tests/differential/README.md#regression-ci-and-local-reproduction)

The child owns its runtime instance and thread. The generated entry owns its stack and lends it to the runtime for the invocation. The parent owns the capture pipes. Direct kernel writes keep markers observable after terminal child failure, and `subprocess.run` drains both pipes, closes their descriptors and reaps the child, including timeout termination. The guard mode invokes one service and starts one child per input. ASan/UBSan instrumented and exercised the compiler, CLI, C++ harness and native runtime. Generated IR was lowered through `llc` and exercised with LLVM's guest-memory guards.

This regression covers a generated scalar store followed by the supported getter on macOS ARM64. Recoverable fault handling, guest concurrency and native Windows execution remain outside its validation.

## Defects and follow-up

No semantic correctness defect was reproduced. To cover the initial four gaps, the audit extended one integer unit and one differential fixture, and added one differential fixture, one negative lifting test and one image integration test.

**Service-side-effect gap closed.** The linked harness independently observes exactly one marker after the valid store and zero markers with SIGTRAP after the invalid store in baseline and O2. The disposable misplaced-call mutation fails the marker assertion in both variants. The follow-up extends the checked-memory assembly, its fixture exports, native harness and Python integration, with validation recorded above. [Guard observations and validation](#terminal-guard-before-getlasterror) · [Fault observations proposed in the review](rosetta-lessons.md#differential-tests-and-benchmarks)

Native Windows x64 execution remains unverified. The audit found no need for a production fix. T1 conditions before-and-after kernel measurements on such a fix, so translation time, native execution time and text size remain separate T3 work.
